# Reproducibility and provenance

## What is frozen

- candidate identity and N03 numerical parameters;
- Dataset501 channel and label semantics;
- model trainer/plan/fold identities;
- best-checkpoint ensemble policy;
- learned-gate feature and reconstruction implementation;
- dependency locks and base-image digest;
- Docker input/output contract;
- preserved Docker TAR and image digests.

## What is not in Git

- challenge images and labels;
- checkpoints and learned-model binaries;
- OOF/test probabilities and predictions;
- platform score CSVs;
- Docker archive;
- SSH, registry, Synapse, or GitHub credentials.

## Numerical equivalence boundary

The preserved Docker image is the authoritative executable artifact. Running
that image with the same NIfTI inputs should reproduce its own output
deterministically. Retraining is a method reproduction and is not expected to
produce byte-identical checkpoints.

Historical predictions generated by a different preprocessing/export path may
not be voxel-identical even when the model weights and postprocessing logic are
unchanged. Therefore equivalence audits must localize differences separately
at:

1. preprocessed tensors;
2. per-model probability arrays;
3. XF12 anchor masks;
4. N03 proposal/acceptance decisions;
5. final NIfTI geometry and label arrays.

Do not infer a postprocessing bug solely from final-mask differences.

## Release verification

```bash
python -m pytest -q
python scripts/verify_release.py . --output release_audit.json
git status --short
git ls-files
```

The release verifier rejects private model/data binaries, common credential
assignments, and workspace-specific absolute paths.
