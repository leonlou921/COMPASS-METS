# Public BraTS-METS Training Pipeline Design

## Goal

Turn `leonlou921/brats-mets-MicroBT` into a public, code-only repository that
reproduces the final ResEncM, ResEncXL, focal-Tversky donor, learned-gate,
XF12, N03, and UTILITY_V4 lineage with Python and Bash. The repository must
not require Docker and must not contain challenge data, trained weights, test
probabilities, or private infrastructure details.

## Scope

The repository includes:

- a pinned, complete nnU-Net source tree;
- Dataset501 conversion, region-label mapping, and preprocessing code;
- the final ResEncM and ResEncXL five-fold training paths;
- the focal-Tversky donor used by the final fusion;
- SmallLesionOS and ComponentSmallLesionOS as directly relevant ablations;
- OOF feature generation and LCv1/LCv2/RGv3/UTILITY_V4 training;
- M/XL/FT five-fold probability inference;
- XF12 structured probability, N03 parent-supported ET, and UTILITY_V4;
- ordered Python/Bash entrypoints, tests, and reproducibility documentation.

The repository excludes:

- all Dockerfiles, Docker build scripts, container runtime helpers, and Docker
  release documentation;
- challenge data, labels, case lists, and test case identifiers;
- checkpoints, learned `joblib` models, probability arrays, NIfTI predictions,
  Docker archives, and frozen reference ZIP files;
- SyntheticTumorAug and other abandoned experimental trainers that are not
  part of the final lineage or its selected key ablations;
- broad parameter sweeps and historical rescue variants;
- final 179-case output checking, flat submission ZIP creation, CRC checks,
  and submission SHA256 generation.

## nnU-Net Source and Trainers

The repository vendors the complete nnU-Net tree pinned by
`third_party/nnUNet.UPSTREAM`:

- upstream: `https://github.com/MIC-DKFZ/nnUNet`;
- commit: `86606c53ef9f556d6f024a304b52a48378453641`;
- upstream version: `2.6.2`;
- license: Apache-2.0.

The upstream license and attribution remain intact. Project-modified files are
identified in `THIRD_PARTY_NOTICES.md` and by a short modification notice in
the affected source files.

Custom trainers have one source of truth under:

```text
third_party/nnUNet/nnunetv2/training/nnUNetTrainer/variants/brats_mets/
```

The retained trainer set is:

- the standard nnU-Net trainer with ResEncM plans;
- the standard nnU-Net trainer with ResEncXL plans;
- `nnUNetTrainer_ResEncM_DiceCEFocalTverskyFT`;
- `nnUNetTrainer_ResEncM_SmallLesionOS`;
- `nnUNetTrainer_ResEncM_ComponentSmallLesionOS`.

Duplicate copies under `training/nnunet_trainers` are removed. The
SyntheticTumorAug trainer is not retained because it is outside the approved
final lineage and selected ablation boundary.

## Data and Artifact Boundary

The public repository operates on user-provided inputs. It never downloads or
redistributes BraTS data.

All runtime locations are provided through:

```bash
export BRATS_RAW=/path/to/raw
export NNUNET_RAW=/path/to/nnUNet_raw
export NNUNET_PREPROCESSED=/path/to/nnUNet_preprocessed
export NNUNET_RESULTS=/path/to/nnUNet_results
export BRATS_WORK=/path/to/work
export BRATS_OUTPUT=/path/to/output
```

No checked-in configuration contains an absolute workstation or server path.
Dataset conversion accepts a user-owned raw root and creates Dataset501 under
`NNUNET_RAW`. Public examples use synthetic identifiers only.

Model weights are generated by the training scripts or supplied by the user.
The repository documents:

- the expected trainer, plan, configuration, and fold directory layout;
- the required checkpoint filename;
- how to create a local weight manifest;
- how to verify local file hashes when a manifest is available.

The repository does not publish weight URLs or hashes for files that are not
publicly distributable.

## Ordered Workflow

The public workflow is:

```text
user-provided BraTS data
  -> Dataset501 conversion and label validation
  -> nnU-Net fingerprint, planning, and preprocessing
  -> ResEncM five-fold training
  -> ResEncXL five-fold training
  -> focal-Tversky and selected small-lesion five-fold training
  -> OOF probability and feature generation
  -> LCv1, LCv2, RGv3, and UTILITY_V4 training
  -> M, XL, and FT five-fold test probability inference
  -> XF12 structured probability
  -> N03 parent-supported ET
  -> UTILITY_V4 three-state add-only gate
  -> final segmentation directory
```

The workflow intentionally stops at the final segmentation directory. It does
not implement final 179-case checking or submission ZIP packaging.

## Shell Interface

Every public Shell entrypoint:

- starts with `set -euo pipefail`;
- provides `--help`;
- uses the six documented environment variables;
- validates its required inputs and previous-stage manifest;
- refuses to overwrite an existing stage root;
- skips only folds whose completion marker and required outputs are valid;
- records the command, repository commit, configuration, fold, start/end
  times, and produced artifact paths;
- never embeds an SSH endpoint, credential, private absolute path, or remote
  process-control command.

The scripts call Python modules for validation and scientific logic. Shell
code performs ordering, environment setup, fold scheduling, and fail-closed
handoffs only.

## Scientific Pipeline

### ResEncM and ResEncXL

ResEncM and ResEncXL use Dataset501, `3d_fullres`, five explicit folds, and
`checkpoint_best.pth` for downstream probability inference. `fold_all` is not
treated as five-fold cross-validation.

The M and XL paths share preprocessing and label semantics but retain their
own plan identifiers and result roots.

### Focal-Tversky and Small-Lesion Ablations

The final donor is trained with the retained Dice+CE+Focal-Tversky trainer.
SmallLesionOS and ComponentSmallLesionOS remain runnable as key ablations.
Their sampling and component policies are configured explicitly rather than
through undocumented module constants.

### Learned Gates

The learned-gate package contains:

- case and component feature extraction;
- leakage-safe OOF fold assignment;
- LCv1 case scoring;
- LCv2 component scoring;
- separated RGv3 ET scoring;
- UTILITY_V4 existence and geometry models;
- frozen three-state gate inference.

Training code verifies that no case appears in both a fold's training and
validation partitions. Test-time inference loads only final models trained
from the complete training set.

### Final Postprocessing

The final postprocessing chain is:

```text
M/XL/FT probabilities
  -> XF12 structured probability
  -> N03 parent-supported ET
  -> UTILITY_V4
```

UTILITY_V4:

- evaluates the fixed disconnected ET candidate pool;
- requires `v2_component_probability`,
  `v4_existence_probability`, and `v4_geometry_probability` to be at least
  `0.75` for acceptance;
- rejects a candidate when either utility-v4 probability is below `0.50`;
- applies the frozen RGv3 ET cutoff `0.7702616034384248`;
- adds accepted ET only;
- preserves existing N03 voxels and RC priority;
- preserves `ET subset TC subset WT`;
- does not rerun global V2 after the ET addition.

## Error Handling

Each Python stage raises a descriptive error for:

- a missing environment variable or stage manifest;
- unexpected modality names or label values;
- mismatched case sets, image geometry, channel order, or probability shape;
- NaN or infinite probabilities;
- missing folds or checkpoints;
- OOF case leakage;
- a missing learned-model feature;
- an attempt to remove anchor voxels or override RC;
- a non-empty destination that would be overwritten.

Cases with no component proposals are valid. They produce a schema-correct
empty component frame and continue through postprocessing without additions.

## Tests

The public test suite covers:

- Dataset501 conversion, modality naming, and region-label mapping;
- M, XL, focal-Tversky, SmallLesionOS, and ComponentSmallLesionOS trainer
  imports and configuration;
- focal-Tversky numerical values, finite gradients, and deep-supervision
  integration;
- small-lesion and component-aware sampling behavior;
- OOF fold isolation and leakage rejection;
- LCv1, LCv2, RGv3, and UTILITY_V4 feature/model interfaces;
- XF12 structured probability and N03 parent-supported ET;
- UTILITY_V4 thresholds, add-only behavior, hierarchy, RC protection, and the
  empty-proposal case;
- `bash -n`, `--help`, and synthetic smoke tests for every Shell entrypoint;
- privacy scanning, absolute-path scanning, large-file rejection, and
  third-party license retention.

Tests use synthetic arrays and identifiers. They do not depend on private
challenge data, weights, probabilities, or frozen outputs.

## Migration and Publication

Implementation occurs in the isolated branch:

```text
agent/public-training-pipeline
```

The branch starts from the existing utility-v4 source commit and independently
incorporates the empty-proposal fix without modifying the active image
verification worktree.

Migration steps:

1. remove all Docker and submission-packaging surfaces;
2. rename the project package from `n03_docker` to `brats_mets`;
3. consolidate project code into the repository architecture above;
4. deduplicate the custom trainers;
5. add the ordered scripts and documentation;
6. run unit, integration, shell, privacy, license, and large-file checks;
7. inspect the complete diff and stage only intended public files;
8. push `agent/public-training-pipeline`;
9. open a draft pull request against `main`;
10. verify the remote branch and exact commit before merge.

The pull request is not merged until the public checks pass and the remote
contents are independently verified.
